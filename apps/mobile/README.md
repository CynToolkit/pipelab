# @pipelab/mobile

A **Tauri 2.x** shell that runs the Pipelab web interface on **iOS** and **Android**.
It hosts the `@pipelab/ui` build inside a native webview and runs an on-device
Pipelab engine bridge (a WebSocket server implemented in Rust, see
`src-tauri/src/lib.rs`) so the UI can execute automation pipelines without a
separate desktop machine.

This complements the existing Electron desktop app (`apps/desktop`) and the
`@pipelab/plugin-tauri` packager used to ship *other* apps.

## Requirements

- Rust (stable) + the platform targets for mobile:
  - Android: Android SDK/NDK, `rustup target add aarch64-linux-android`
  - iOS: Xcode (macOS only), `rustup target add aarch64-apple-ios`
- `pnpm`, Node.js (see `.mise.toml`)

## Develop

```bash
pnpm install
pnpm --filter @pipelab/mobile dev          # desktop preview (requires webkit2gtk on Linux)
```

## Build for mobile

```bash
pnpm --filter @pipelab/mobile android      # builds the Android APK/AAB
pnpm --filter @pipelab/mobile ios          # builds the iOS app (macOS only)
```

Use `android:open` / `ios:open` to open the project in Android Studio / Xcode.

## How it connects to the engine

The Rust side starts a WebSocket server on `ws://127.0.0.1:31753` and implements
the same IPC protocol the desktop CLI exposes. The bundled UI talks to it exactly
like it talks to the `@pipelab/cli` over the network, so pipelines (including
Tauri-packaged builds produced by `@pipelab/plugin-tauri`) run unchanged on
mobile.

## Project layout

```
apps/mobile
├── package.json          # tauri CLI scripts (dev/build/android/ios)
├── tauri.conf.json       # Tauri 2 config with app.mobile + bundle.targets
├── src/                  # frontend (src/ui is generated by `pnpm build:ui`)
└── src-tauri/            # Rust app, capabilities, icons
    ├── src/lib.rs        # mobile entry point + engine WebSocket bridge
    └── capabilities/     # permission sets for desktop & mobile
```
